Open source / macOS 14+ / stock Hermes plugin API

Native Messages for stock Hermes.

Native iMessage and SMS on macOS, backed by the local imsg CLI. Every ordinary inbound reply uses the exact Messages chat rowid that produced it, with trusted native replies and capability-gated actions when the private bridge is available.

No Hermes core fork. No participant lookup for replies. No alternate destination.

Basic and private

A visible capability boundary.

Basic operation uses local database reads and Messages automation with SIP enabled. Native private actions require the optional bridge and deliberate operator setup.

Recommended starting point

Use the basic path on a normal SIP-enabled Mac.

Turn off bridge re-arm and read receipt attempts until the private environment has been evaluated separately.

platforms:
  imsg:
    extra:
      auto_launch: false
      send_read_receipts: false

Install and configure

A local plugin with explicit prerequisites.

The supported path keeps Hermes core unchanged. The installer creates the plugin symlink, preserves a configuration backup, and runs a discovery probe.

It does not install imsg, grant TCC permissions, change SIP, sign in to Messages, or restart Hermes.

  1. 01

    Prepare the Mac

    Use macOS 14 or later with Messages.app signed in. Grant Full Disk Access to the launcher chain and Automation permission for sends.

    brew install steipete/tap/imsg
  2. 02

    Install the plugin

    Clone the repository and run the local installer from the checkout.

    git clone https://github.com/promptclickrun/hermes-imsg-cli
cd hermes-imsg-cli
scripts/install-local.sh
  3. 03

    Start from default deny

    Keep direct-message and group allowlists separate. Rules are first-match, and silent_drop remains the safe fallback.

    platforms:
  imsg:
    enabled: true
    extra:
      auto_launch: false
      send_read_receipts: false
      reaction_notifications: off
      allowed_handles: ["+12025550101"]
      group_allowed_handles: ["+12025550101"]
      group_action_admins: ["+12025550101"]
      allowed_chats: ["42"]
      require_mention: true
      fallback_action: silent_drop

Security properties

Failures remain explicit.

These properties are enforced at subprocess and adapter boundaries and covered by the repository test suite.

Exact reply destination
Ordinary replies use the trusted rowid and ignore framework reply correlation. Native threads require the explicit reply action and a same-chat message lookup.
Silent Tapbacks
Reaction events are not subscribed to by default and are dropped before agent processing when disabled. Opt-in modes can initiate agent turns.
Same-chat mutations
Message and poll IDs are verified in the selected conversation. Edit and unsend also require bot authorship.
Owner-only group changes
Non-local callers need an authenticated group action owner; group admission and unauthenticated API context cannot change identity or membership.
Fail-closed capability and confirmation
Malformed status, missing methods or selectors, invalid targets, and empty or non-object confirmations are errors.
Regular files only
Outbound attachments reject symlinks, directories, FIFOs, sockets, devices, and missing paths before send.
Restricted diagnostics
Raw watch payloads are never logged. Diagnostics redact phone numbers, email addresses, home paths, and GUID-like identifiers. Plugin-owned decision and action fields omit the known chat rowid.
Restrictive cursor state
The resumable rowid cursor is written atomically with owner-only 0600 permissions.
Operator-owned permissions
The plugin does not edit TCC, disable SIP, install bridge code, or sign in to Messages.

Data boundary

This repository invokes a local imsg executable. Hermes, model providers, and enabled tools have separate data flows outside this plugin's control. Review each before connecting personal Messages.
